## 更新頻度の高いコンテンツ(プレイリスト・メイク)

載せたいもの:

1. **プレイリスト** — 曲が好き。聴いているもので人柄を伝える
2. **スキンケア手順・メイク手順** — メイクが好き。手順やアイテムを紹介

どちらも頻繁に更新するので、**コードを触らずデータだけ編集すれば反映される形**にする。

### 方針: リポジトリ内の構造化データファイル(第一段階)

```
content/
  playlists/
    2026-08-summer.yaml      # タイトル、テーマ、曲リスト(曲名/アーティスト/リンク)、ひとこと
  beauty/
    skincare-morning.yaml    # 手順(ステップ順)、アイテム(名前/ブランド/リンク)、メモ
    makeup-daily.yaml
```

- YAML(またはMDX)をビルド時に読み込んで自動レンダリング。ファイルを1個追加・編集して push すれば更新完了
- スキーマは Zod などで検証し、フォーマット崩れをビルドで検知する
- 曲は Spotify / Apple Music のリンクを持たせれば埋め込みプレイヤーにも展開できる

### 発展形(必要になったら)

- **外部データ連携**: Spotify API で「いま聴いてる曲」「最近のヘビロテ」を自動取得(design-direction の「実世界との連動」演出と直結)
- **管理画面**: 更新が git 経由では面倒になってきたら、Elysia.js + Drizzle ORM で軽い管理UIを作る(技術方針と一致)
