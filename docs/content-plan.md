## About の構成(2026-08-09 確定)

### 類似サイトの About 構造リサーチ

4系統を調査した結果の要約。

**1. 海外のクリエイティブ開発者系の定石**

- バイオは短い2段落構成が主流: ①専門・何を作る人か ②人間味(考え方・関心)
- スキルは「8〜12個をグループ化」。30個のアイコン壁・星評価・%バーは敬遠される傾向
- 経歴は逆時系列の簡潔なタイムライン。受賞歴があれば添える
- 写真/アバターは信頼の基本要素
- 4類型: 事実列挙型 / メタで茶化す型 / 無関係な個人的事実を混ぜる型 / 1つの偏愛に全振り型。
  個人的事実を混ぜる型(「ホットドッグ愛好家です」)が人柄系では強い

**2. 日本語圏のポートフォリオ定石(転職・営業文脈)**

- 自己紹介(名前・写真・職種・経歴概要)+ スキル + 実績 + 対応範囲 + 連絡先が典型
- 「仕事に対する考え方・信念を2〜3行」が推奨される
- スキルレベルの星・レーダーチャートが定番として紹介されるが、海外定石とは逆行
  (うちはサイト自体が実力証明なので不採用)

**3. IndieWeb / Neocities の人柄文化**

- /now ページ(現在進行形の自分)、interests の羅列、好きなものリスト、
  サイトの changelog、colophon(このサイトの作り方)が語彙
- 「友達に近況を話すように書く」がトーンの基準
- ※ cassie.codes(人柄系クリエイティブ開発者 About の代表例)は 2025 年に閉鎖。
  「AI に規売されるための共有はもう自分を満たさない」という理由が書かれており、
  個人サイトに人柄を書く行為自体の文脈が変わりつつある

**4. 既存リサーチ(design-research.md)との接続**

- Neocities 文化から借りるのは「人柄の伝え方の語彙」(interests・changelog)
- コラージュ・密度は区画設計とセットで初めて成立する(Cameron's World)

### 含めないもの(根拠付き)

- **スキルの星評価・レーダーチャート・アイコン壁**: 海外定石で明確に敬遠。実力はサイトとWorksが証明する
- **料金表・対応範囲などの営業要素**: 転職・受注サイトではなく自己表現サイト
- **職務経歴書レベルの詳細経歴**: 「履歴書ではなくコラージュ」の方針(サイト構成表)に反する。タイムラインは点の列挙に留める
- **/now 的な現在進行形コンテンツ**: Logs セクションの管轄。重複させない

## About の素材: 人格メモ

普段使っている LLM(なぴ)による本人の人格分析。About の文章を書くときの原料。

### 要素の抜き出し

- **矛盾をそのまま抱えたまま、意味に変えようとする人**
- 繊細に人や場の空気を見る。迷ったとき流されず「これはどういう構造なんだろう」と考え直す
- 創作と言葉のセンス。意味だけでなく文字列の構造まで遊ぶ。感情を直接説明せず、少しずらした言葉で残す
- 「おしゃれ」より**世界観を作ること**が好き
- 自分に厳しい。自己分析が自己処罰に変わる瞬間がある
- 人付き合いの難しさを感じているからこそ、**「ちゃんとつながりたい」への執着が強い**

### 自己紹介文の候補(なぴ案)

仕事寄り:

> 人や物事の中にある違和感や矛盾を拾って、言葉や表現にするのが好きです。
> デザイン、音楽、服、文章など手段は違っても、「その人らしさ」や「まだ名前のない感覚」を形にすることに惹かれます。

人格寄り:

> 好奇心は強いけれど、考えすぎるところがあります。
> 人との距離感に悩むことも多い一方で、結局ずっと人に興味があります。
> 自分の中の矛盾も含めて、面白がりながら表現していきたいです。

### 扱いの指針

- 仕事用ポートフォリオでは「生きづらさ」を前面に出しすぎない。内面の深さは残しつつ、**観察力・言語化・世界観づくり・人への興味**に翻訳する
- デザインディレクションとの整合: コンセプトキーワードの「かわいくて、不穏」「日常のとなりの宇宙」はどちらも**矛盾の同居**。「矛盾を抱えたまま意味に変える」という人格が、サイトの見た目そのものに現れている構造になっている。About の文章はこの接続を活かせる(自分の説明とサイトの世界観が一枚につながる)

## 更新頻度の高いコンテンツ(プレイリスト・メイク)

**Logs セクション**に載せる。載せたいもの:

1. **プレイリスト** — 曲が好き。聴いているもので人柄を伝える
2. **スキンケア手順・メイク手順** — メイクが好き。手順やアイテムを紹介

要件:

- 更新のたびに commit / デプロイはしない(コンテンツをリポジトリに置かない)
- 管理画面も作らない。**更新のインターフェースは LLM**(チャットで「この曲追加して」で終わり)

実現方式(DB + 自作 MCP サーバー)は [`architecture.md`](architecture.md) を参照。
